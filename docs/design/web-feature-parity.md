# qisiTV 网页完整功能对齐

状态：范围及代码审计完成，用户已选择网页操作、本地引擎按需自动启动。功能迁移尚未实施；线上版本仍为 v1.5.17，本文不是已交付功能清单。

## 目标和基线

用户要求 qisiTV 与 BeefTV 的区别在交付形式：qisiTV 通过网页使用，上游通过客户端使用；上游已具备的创作能力全部纳入，不能继续只挑少量修复。

- 当前 qisiTV：`cc973fd9dcd70a813b4aa4e7325e156f8c6574fd`。
- 对齐上游：v2.0.3，`e13263c948fbbada3724442fc2c9ee6aaea6cfa2`。
- 保留 qisiTV 品牌、本机独立项目文件夹、外部 MCP 多客户端以及现有 qisi API / LikeAI 配置。
- 无需画布注册、登录或云端项目库。外部模型服务或技能投稿服务的认证与画布账号分开。
- 新目标覆盖过去“不需要网页内助手”的限制，内置助手与外部 Agent 都须可用。
- 已确认当前网站部署授权。移植保留上游许可证及素材许可证；服务授权不替代外部 API 凭据。

## 已确定的运行方式

用户已选择第一项：

1. 网页是全部操作入口；浏览器能完成的工作在浏览器运行。原生媒体、深度模型和 Node 助手宿主通过同一个本机引擎按需运行，复用现有 MCP 的配对与自动管理体验。素材仍留本机。
2. 所有功能无需本机程序；浏览器不能运行的部分放网站服务器。需要新增计算与任务服务，并上传相关素材，须重新明确存储、删除、成本和隔离方式。

采用网页操作和本机引擎。普通画布继续可以直接使用；需要完整原生能力时自动管理同一引擎。首次安装需要用户本机运行已校验程序，后续以系统唤起入口启动；网页本身不能凭空启动未安装程序。引擎会话与进行中任务独立保活，不能依赖 Codex 一直开着。不扩大项目上传范围，不建立云端工作区。

## 共用业务和保存合同

手动 UI、内置助手、工作流、MCP 共用同一 operation contract。调用包含项目/会话范围、当前修订、幂等操作 ID、执行类型及必要参数。浏览器侧对写入校验并最终提交，禁止运行器直接绕开网页修改同一项目。

资源使用稳定 ID、文件摘要、相对路径和 MIME；可展示临时 URL 不构成资源身份。任务保存执行快照、模型身份、源参数、上游回执和输出绑定；敏感请求头、API Key、连接令牌不进入项目、工作流模板或诊断日志。

工作流定义与修订、助手会话/回合/方案、技能包版本及任务记录须保存在真实目录，IndexedDB 只作缓存。现有项目格式需要显式版本迁移、旧文件备份和失败恢复；不能未经迁移直接改变线上读写格式。

收到上游受理回执后，取消浏览器等待或刷新页面不等于供应商取消。状态未知时查询原任务，禁止自动重新创建付费任务。任何重试都区分查询/取回、未提交重试和新收费生成。

## 服务适配的实证边界

当前 `browser-likeai-client.ts` 拒绝 tools、execution 和非空 textHistory；qisi API 浏览器适配仅允许 Seedream 4.5 图片、Seedance 2.5 视频。助手必须新增真正支持工具调用和多轮会话的文本模型通道，不能把现有单轮任务接口当作完整助手。

LikeAI [官方公开文档](https://task.likeai.pro/api-doc) 已核对到图片 `huoshan_image_super_resolution` 和视频 `tengxun_video_super_resolution`，可用于真实 AI 超清。它们不等于 Topaz；上游四个 Topaz 模型仍需独立适配及可用凭据。检查文档不构成收费生成授权。

上游技能市场服务端不在当前源码内。市场浏览、安装及投稿客户端可以适配，但独立目录/审核服务需要单独实现；不能擅自复制远程用户技能或代用户公开投稿。
