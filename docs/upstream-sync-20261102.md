# 2026-11-02 上游同步

## 来源与范围

本次从已发布的 qisiTV `v2.0.3-web-beta.2`（`dce69fcc`）合并 [BeefTV `9c901178`](https://github.com/glanderness/BeefTV/commit/9c901178cc5e6c4299ed4f4cf5665e0fd136ae75)。此前基线为 `e13263c9`，本次包含 321 个新提交；上游最近发布版本为 v2.1.2。qisiTV 版本号为 `v2.1.2-web-beta.1`。

保留 qisiTV 品牌、网页交付、已配对本机引擎、真实项目目录、独立 qisi API / LikeAI 配置及多 Agent MCP。没有新增画布账号、云端项目数据库或钱包。上游原始许可、署名与第三方条款继续随源码和发行物交付，本次未修改 LICENSE / NOTICE / licenses。

## 合入与适配

- 合入画布外部操作记录与撤销、分镜和助手改进、任务状态恢复、视频兼容播放、首尾帧、导出容错与脱敏失败详情。
- 后端采用上游领域拆分与 Go 1.26，保留本地引擎的授权和项目目录投影。
- 模型能力采用上游新拆分与服务端合同；协议插件升级 v3，并兼容既有命名与版本。
- 前端使用画布 owner epoch 和取消信号，跨项目、节点或引擎配对后的迟到结果不得写入新目标。引擎失败不降级为另一套浏览器工作区。
- 保留 qisiTV 自有构建和下载来源。上游的镜像发布、钱包、付费生成发布回执不作为 qisiTV 的发行能力或验收证据。

## 额外修复

1. 图像转换节点在缓存冷启动时直接引用受保护资源 URL，导致预览空白和下载无授权。现在通过已配对引擎读取真实文件并生成浏览器 blob，回归验证实际下载字节。
2. 绘图文件从真实项目目录恢复时仍写旧缓存格式，新缓存迁移会把已提交版本误判为未保存草稿。现在恢复 committed envelope 并保留目录版本和本地生成序号。
3. 音视频分离进行中删除、替换源节点，或切换画布后，不再向失效目标写回结果。
4. 合并测试运行器的并行执行，同时保留 Chrome 自动发现及共享测试组失败时的非零退出码，避免失败被误报为通过。

## 验证边界

测试使用隔离目录、合成素材与模拟模型响应；没有发起付费生图、生视频或修改用户工作区。引擎安装包、网站发布和跨平台实机验收须以各自结果为准，源代码合并不表示已完成部署。具体命令及最终结果记录在本次合并请求中。

上游结构预算首次用于 qisiTV 时，需要纳入既有本地引擎、项目文件夹和 LikeAI 服务适配的增量。这些是合并前已有产品差异，不能为了满足上游裸基线而删掉功能；在完成本次合并后记录 qisiTV 基线，后续仍只能收紧或明确说明增量。
