# 网站版、本地项目文件夹与 Agent

同一个项目目录请只在一个浏览器中编辑。跨浏览器或不同网站来源的同时写入不受同一把浏览器锁保护；切换浏览器前先等待保存完成并关闭旧页面。

打开 [qisiTV 起司 TV](https://cheeser.link/qisitv/)，使用桌面 Chrome 或 Edge，进入「本地文件与 Agent」。先选择电脑上的项目根目录；以后每个项目都会有自己的真实子文件夹，画布与素材自动写入。普通创作不需要注册、登录或启动本地程序。需要 Agent 操作画布时，在页面选择自己使用的客户端，把对应安装指令交给能在本机执行命令的 Agent。

## 先设置保存位置

1. 在电脑创建一个专门的目录，例如「qisiTV 项目」。
2. 网站进入「本地文件与 Agent」，点击「选择项目文件夹」，选择这个根目录并允许读写。
3. 打开项目列表，新建项目。导入参考素材、添加节点和连线后，等待画布顶部显示「已写入项目文件夹」再关闭网页。
4. 需要生成时，在「模型配置」填写自己的 LikeAI API Key、拉取模型，再选择模型和参考素材。

根目录中的项目结构如下。目录名称包含项目名称与 ID；在画布中改名不会移动已经创建的目录。

```text
qisiTV 项目/
└── 我的广告片-项目ID/
    ├── project.qisitv.json
    ├── references/
    ├── images/
    ├── videos/
    ├── audio/
    ├── exports/
    └── .qisitv/
        └── revision-1.json
```

`project.qisitv.json` 保存画布、节点、连线、修订号和媒体索引；`references` 保存导入素材的副本，`images`、`videos`、`audio` 存放生成媒体，`exports` 保存通过应用导出的文件，`.qisitv` 保存之前的项目修订。媒体采用内容摘要作为文件名并保留扩展名，可以直接在 Finder 或文件管理器中查看。不要单独移动、改名或替换项目内的媒体文件；恢复时会检查文件大小与摘要。

磁盘文件夹是正式保存位置。IndexedDB 仍用于目录授权句柄、媒体缓存、模型配置及生成任务状态，但它不再是已保存项目的唯一副本。API Key、连接令牌不写入项目文件；复制项目不会复制这些配置。

浏览器需要用户点击按钮授权目录，网站不能直接指定电脑上的绝对路径。当前目录功能要求桌面 Chrome / Edge；Safari、Firefox 和不支持目录 API 的内嵌浏览器会提示更换浏览器，不会将仅存缓存显示成已写入文件夹。权限失效时点击「重新授权」。

## 恢复项目与迁移旧数据

重新打开网站后，应用会恢复已有目录授权；如浏览器要求再次授权，按界面提示操作即可。清理网站数据或换电脑后，把完整项目子文件夹放入一个根目录，再在网站选择该根目录，即可从项目文档与媒体文件恢复画布。选择的是包含多个项目子文件夹的根目录，不是单个项目内的 `images` 或 `videos` 目录。

之前仅存在当前浏览器中的项目会保留。选择根目录后，页面若显示「还有若干个项目只在浏览器缓存中」，点击「保存这些项目到文件夹」完成迁移。程序先写媒体，再写项目文档；媒体缺失、远程结果尚未下载或磁盘写入失败会明确报错，不会删除旧缓存后声称迁移成功。

生成中的任务状态与 LikeAI 配置仍有浏览器缓存依赖。搬动项目、清理网站数据或换浏览器前，先等任务结束并确认结果已写入文件夹；新浏览器需重新填写 Key。同一根目录内如果有两个相同项目 ID 的复制品，读取会被拒绝。

## 让你的 Agent 操作同一个画布

页面提供 Codex、WorkBuddy、Claude Desktop、Claude Code、OpenClaw、Hermes、CodeBuddy、Cursor、VS Code 和通用 MCP 十个入口。主流程都是安装一次、让 Agent 获取配对码、网页确认连接。无需手选系统包或另外保留服务终端。

**Agent、连接器和浏览器必须运行在同一台电脑上。** 远程服务器上的 OpenClaw / Hermes、云端 Agent、SSH 或容器中的进程不能直接使用这台电脑的回环服务。Claude 网页版不支持本方案的本机 stdio MCP；请选择 Claude Desktop 或在本机运行的 Claude Code。VS Code 远程开发时须使用本机用户配置。

### 1. 选择客户端，复制安装指令

在页面选好客户端后，把完整指令发给 Agent。它先检查 Git、Node.js 18+ 和该客户端的 MCP 能力；缺少环境或安装失败时应明确说明，不能声称已经装好。

Codex 使用公开插件 **`qisitv@qisitv`**，由 Agent 执行：

```bash
codex plugin marketplace add https://github.com/wyuzhi/qisiTV.git --ref main
codex plugin add qisitv@qisitv
```

其他客户端使用同一份本机 MCP 程序。安装指令让 Agent 把官方仓库 `https://github.com/wyuzhi/qisiTV.git` 的 `main` 分支克隆到临时目录，在仓库内执行：

```bash
node plugins/qisitv/scripts/prepare.mjs --json
```

准备程序自动识别系统和架构、下载并校验程序，将程序和许可证保留在稳定的用户目录，然后只输出一个 JSON 对象：

```json
{"command":"/absolute/path/to/qisitv-connect","args":["mcp"]}
```

示例路径必须替换为本次输出的真实 `command`，Windows 输出指向 `.exe`。`prepare` 不修改任何客户端配置，也不启动 MCP；Agent 接着按所选客户端的格式添加 `qisitv-web`。修改已有文件前备份，只合并这一项，保留其他服务和字段；同名配置已存在时先核对，不能盲目覆盖。配置指向准备结果中的固定路径，完成后可删除临时克隆目录。

Claude Desktop 的普通聊天若没有本机命令执行能力，不能自行完成准备。可以让另一个具有本机执行能力的 Agent 运行上述步骤，再将生成的配置粘贴到 Desktop 设置；不能把一段聊天回复当作安装完成。其他客户端受权限或运行环境限制时也采用同样方式。网页按所选客户端提供对应安装指令和官方说明，真实配置由 Agent 根据 `prepare` 的输出合并。

### 各客户端的配置入口

下表中 `PREPARED_COMMAND` 表示 `prepare` 返回的绝对路径，作为单个命令参数传入，不能把路径与 `mcp` 拼成一个字符串。客户端命令随版本变化时，先检查其 `--help`；不要擅自安装或切换 Agent。

| 客户端 | 配置方式 |
| --- | --- |
| Codex | 上述 marketplace 插件；安装后新建任务加载工具。 |
| WorkBuddy | 插件 → MCP 服务器 → 配置 MCP（较新版为连接器 → 自定义连接器），先备份用户级 `~/.workbuddy/mcp.json`，向 `mcpServers["qisitv-web"]` 合并 `prepare` 返回的 `command`、`args`，保留其他设置。检查服务绿色状态，再调用 `qisitv_pair` 确认本机 stdio 连接。 |
| Claude Desktop | 设置 → Developer → Edit Config，向打开的 `claude_desktop_config.json` 合并 `mcpServers.qisitv-web`，填写 `command`、`args`；完全退出并重新打开 Desktop。 |
| Claude Code | `claude mcp add --transport stdio --scope user qisitv-web -- PREPARED_COMMAND mcp`；用 `claude mcp get qisitv-web` 核对。 |
| OpenClaw | `openclaw mcp add qisitv-web --command PREPARED_COMMAND --arg mcp`；用 `openclaw mcp doctor qisitv-web --probe` 检查。配置为 `~/.openclaw/openclaw.json` 的 `mcp.servers.qisitv-web`。 |
| Hermes Agent | `hermes mcp add qisitv-web --command PREPARED_COMMAND --args mcp`，`--args` 放最后；配置为 `~/.hermes/config.yaml` 的 `mcp_servers.qisitv-web`，新会话或 `/reload-mcp` 加载。 |
| CodeBuddy | **CLI**：`codebuddy mcp add --scope user qisitv-web -- PREPARED_COMMAND mcp`，再 `codebuddy mcp get qisitv-web`。**IDE**：设置 → MCP → Add MCP，合并 `mcpServers.qisitv-web`，使用 `type: "stdio"`、`command`、`args`；不假设 IDE 与 CLI 共享配置。 |
| Cursor | 在本机 `~/.cursor/mcp.json` 合并 `mcpServers.qisitv-web`，使用 `type: "stdio"`、`command`、`args`；在 MCP 设置确认启用。项目专用配置为 `.cursor/mcp.json`。 |
| VS Code | 命令面板执行 `MCP: Open User Configuration`，在本机用户 `mcp.json` 合并 `servers.qisitv-web`，使用 `type: "stdio"`、`command`、`args`；通过 `MCP: List Servers` 启动并确认信任。其根键是 `servers`。 |
| 通用 MCP | 客户端必须支持本机 stdio：启动命令为真实 `command`，参数为 `["mcp"]`。按该客户端官方格式配置；仅支持远程 HTTP 的入口不能使用。 |

CodeBuddy CLI 当前推荐 `~/.codebuddy/.mcp.json`，兼容旧 `~/.codebuddy/mcp.json` 和 `~/.codebuddy.json`，按存在顺序选择读写文件，优先使用其 CLI 管理。Claude Desktop 常见路径为 macOS 的 `~/Library/Application Support/Claude/claude_desktop_config.json`、Windows 的 `%APPDATA%\Claude\claude_desktop_config.json`；以设置实际打开的文件为准。

字段与命令来源：[WorkBuddy](https://www.workbuddy.ai/docs/zh/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)、[Claude Desktop](https://modelcontextprotocol.io/docs/develop/connect-local-servers)、[Claude Code](https://code.claude.com/docs/en/mcp)、[OpenClaw](https://docs.openclaw.ai/tools/mcp)、[Hermes 配置](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference/)与[CLI 源码](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/subcommands/mcp.py)、[CodeBuddy CLI](https://www.codebuddy.ai/docs/cli/mcp)与[IDE](https://www.codebuddy.ai/docs/ide/User-guide/MCP)、[Cursor](https://cursor.com/docs/mcp)、[VS Code](https://code.visualstudio.com/docs/agent-customization/mcp-servers)。这些是配置指引，不表示所有客户端都经过实机验收。

### 2. 加载工具，获取配对码

> 使用 qisitv-web，调用 qisitv_pair 获取配对码，不要生成素材。

按客户端提示重新加载工具或开启新会话，Codex 使用新任务。`qisitv-web` MCP 自动启动或复用本机服务。`qisitv_pair` 返回临时配对码与网页入口，获取配对码不要求网页已连接，也不提交生成任务。页面提供单独的「复制连接指令」按钮；工具尚不可见时先解决加载问题，不能编造配对码。

### 3. 网页输入配对码

把 Agent 返回的配对码粘贴到网站「本地文件与 Agent」，点击「连接」。浏览器询问是否允许访问本地网络时选择允许。目录选择和网页配对仍需本人确认，安装或配置 MCP 不会自动授权访问项目。

连接成功后回到项目列表，打开要操作的画布，再发送下面的免费试用指令。它与获取配对码的指令是两个独立步骤：

> 使用 qisitv-web 连接的画布。先列出会话，读取我当前打开的项目和选区，然后在空白处添加一个文字节点，内容是「第一个镜头的创作思路」。先不要调用付费生成。

节点应出现在当前网页，并自动保存到该项目文件夹。选中参考图后，可以继续说「使用我选中的两张图作为参考，连接到一个视频节点，先不要生成」。Agent 通过 `canvas_current` 和画布数据读取真实选区，不靠最近打开的项目猜测目标。

使用期间保持网页打开。连接器由 MCP 在后台管理，只监听 `127.0.0.1:17372`，无需向公网开放端口。刷新或重新打开网页后需要重新配对；配对码有效十分钟且只能使用一次。需要新码时再让 Agent 调用 `qisitv_pair`。多个网页已配对时，让 Agent 先执行 `canvas_list_sessions` 选择目标。

插件名称是 **`qisitv`**，它提供的 MCP 名称是 **`qisitv-web`**，操作已配对的网站画布。旧的同名 **`qisitv` MCP** 则操作原本机 Go 工作区；这是不同入口，项目不会自动混合。已有旧工具时，请在操作指令中明确写 `qisitv-web`。

### 生成授权与失败恢复

画布编辑、连线、导入和模型查询本身不提交收费生成。让 Agent 生图或生视频时，明确指定模型、数量或时长及同意的费用范围。`task_submit` 要求 `consent.approved=true`、授权范围、目标节点、最新 `baseRevision` 和稳定的 `idempotencyKey`；每次只提交一个任务。

提交前先把不含密钥的意图回执写入项目，再调用 LikeAI。相同请求使用相同幂等键会复用任务；同一键改成另一个请求会被拒绝。掉线、超时或刷新不会自动重新提交收费任务。没有供应商任务编号时，先在 LikeAI 核对；已有结果但画布保存失败时，恢复文件夹权限后让 Agent 执行 `task_apply_result`，无需重新生成。

浏览器是项目文件的唯一写入者。连接器通过 WebSocket 转发 MCP 命令，网页复用手动画布的状态和保存逻辑处理，再等待文件写入成功后返回。修改包含修订检查；用户同时编辑造成冲突时会拒绝旧命令，Agent 应重新读取后再操作。

## 请求与保存

LikeAI 接口没有开放浏览器跨域请求，因此网站提供固定目的地的 `/api/qisitv/likeai/` 转发。密钥、提示词与本次参考素材会经过网站函数，再发给 LikeAI；应用不在网站服务器建立账号、数据库或素材存储，不记录请求正文和密钥。LikeAI 自身的任务和临时素材保留规则由服务商决定。

LikeAI Key 只在网页模型配置中填写，不放到 MCP 命令、提示词或项目文件。连接器本身不接收模型 Key；它的配对令牌只用于本机连接。

当前三处大小限制不同：

- Agent 从本机导入画布的单个媒体文件最多 **32 MiB**；更大的本地素材可在网页手动导入。
- 网页向 LikeAI 上传单个生成参考文件最多 **4,000,000 字节**。成功导入画布不代表它满足生成上传限制；超限时需缩小素材或使用服务商可访问的 HTTPS 素材地址。
- 单个生成结果的自动下载最多 **128 MiB**。超限或下载不完整时，保留结果链接并提示，用户可从原链接下载后手动导入；不会再次生成。

转发仅接受明确列出的 LikeAI 路径，不接受任意上游地址。结果下载通过任务编号查询并验证来源，不会把 API Key 发给媒体 CDN。媒体先保存、项目文档后提交；「已写入项目文件夹」只表示实际磁盘写入已完成。权限撤回、磁盘写入失败或外部修订冲突会保留明确错误，不能当作保存成功。

## 构建到网站

在仓库根目录运行：

```bash
./scripts/export-qisitv-website.sh /absolute/path/to/personal-site
```

脚本调用 `scripts/build-qisitv-connect.sh` 构建六个平台连接器，再设置 `VITE_QISITV_BROWSER_ONLY=1` 和 `QISITV_WEB_BASE=/qisitv/` 构建前端，复制到 Astro 网站的 `public/qisitv/`。下载包复制到 `public/qisitv/downloads/`，`deploy/website/` 中的转发函数与对应 Vercel 路由也一并更新。网站目录需要已有 `vercel.json`。

网站采用 hash 路由：画布地址为 `/qisitv/#/canvas/ID`，本地设置页为 `/qisitv/#/local`。默认桌面构建仍使用原本地 Go 服务，见[本地 Agent](/docs/backend/local-agent)。部署与测试记录需以实际执行结果为准；构建通过本身不等于六个平台安装验证或付费模型生成验证。
