## 规则

BeefTV 客户端与本地后端在提交生成任务或执行工作流时，不再按本地字符数、UTF-8 字节数或 UTF-16 单位数提前拦截提示词，也不自动截断提示词。提示词长度上限统一交由当前所选渠道与上游服务商接口校验。

## 模型能力配置中的字段说明

- **视频模型（`video.references`）**：默认 `promptMaxChars` 与 `promptMaxUtf16Units` 均为 `0`，表示本地不预置协议或型号上限。若用户在自定义渠道配置中显式填写了 `0` 至 `1000000` 之间的数值，配置规范化会保留该配置值，但任务参数校验仍将提示词长度交由上游接口判定，避免因不同中转线路或接口版本差异造成本地误拦。
- **图片与文本模型（`image.promptMaxChars` / `text.promptMaxChars`）**：通用能力配置默认值为 `32000`（自定义保存时配置校验要求为正整数），特定内置图片模型合同（如 `hy-image-v3`、`midjourney-v8.2`）也会直接声明自身的 `0` 默认值；无论配置字段取值如何，后端任务提交校验同样已移除本地字符数与字节数拦截，实际长度限制以上游接口返回为准。

## 注意事项

- **不拦截不等于模型全部遵循**：本地放行长提示词只保证请求不被客户端提前拒绝或截断；模型是否能完整遵循长文中的人物对应、服装、台词、镜头运动与时长要求，仍取决于具体模型能力，请以实际生成结果为准。
- **素材编号仍做一致性检查**：虽然提示词长度不再本地拦截，图片与视频生成在提交前仍会核对明确的 `IMAGE N` 素材引用表，防止已知素材编号与实际上传槽位不一致时直接发起付费生成（详见[Seedance 任务模式与参数](./seedance-task-constraints.mdx)）。
