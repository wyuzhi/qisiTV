# 写一个技能

技能告诉创作助手一件事该怎么做。BeefTV 的技能遵循 [Agent Skills 标准](https://agentskills.io/specification)：在 Codex、Claude Code 等工具里能用的技能，放进 BeefTV 也能用。格式细节看标准，这一页只讲 BeefTV 特有的部分。

## 最小的技能

一个技能就是一个文件夹，里面有一个 `SKILL.md`：

```markdown
---
name: storyboard-review
description: 检查分镜脚本的节奏和镜头衔接。当用户要求审分镜或看看脚本有什么问题时使用。
---

# 审分镜

1. 用 `canvas_get` 读出分镜脚本。
2. 逐行检查：景别是否跳得太大，时长加起来是否超出目标。
3. 列出问题，每条写清镜号和改法。
```

`description` 决定助手什么时候想起这个技能，要写清做什么、什么时候用。

## 装进 BeefTV

| 方式 | 怎么做 |
| --- | --- |
| 上传 | 在技能库点「导入文件」，选 Markdown 或 ZIP 技能包 |
| GitHub | 在「导入文件」里选 GitHub，填仓库地址，可以指定分支和子目录 |
| 插件 | 放进插件包，在 `package.json` 写 `"pi": { "skills": ["./skills"] }` |
| 技能市场 | 在技能市场浏览 BeefTV 市场与公共技能目录（skills.sh），确认风险后安装 |

技能库收录 BeefTV 官方提供的技能，以及用户通过 BeefTV 创建、导入、市场安装或安装 BeefTV 插件获得的技能。外部文件中的技能可由用户选择 Markdown 或 ZIP 后导入。

插件带的技能跟着插件走：停用或卸载插件时一起移除。

## 规则

| 项目 | BeefTV 的规则 |
| --- | --- |
| `name` | 必填，最多 80 字，可以用中文。没写时从标题推断 |
| `description` | 必填，超过 1024 字的部分会被截掉。没写时从正文推断 |
| 包大小 | 解压后最多 200MB。不限文件数量和单个文件大小 |
| 包内容 | 只能有一个 `SKILL.md`，不能有软链接 |

这里比标准宽松：标准要求 `name` 用小写字母、数字和连字符，最多 64 个字符。要在其他工具里也能用，就按标准写。

## 脚本

技能包里可以带 `scripts/` 或 `script/` 目录。创作助手需要运行脚本时，会先在右侧对话栏发出确认卡片，列出脚本路径、运行方式、启动参数与超时时间，由你点击「运行脚本」或「本对话始终允许」后才会执行。

| 脚本后缀 | 运行方式 | 环境要求 |
| --- | --- | --- |
| `.js`、`.mjs`、`.cjs` | Node.js | 桌面端自带 Node.js 运行时，无需额外安装 |
| `.py` | Python 3 | 需要电脑上已安装 `python3`（Windows 支持 `python3`、`python` 或 `py -3`）并加入系统 `PATH` |
| `.sh`、`.bash` | Bash | macOS / Linux 使用系统 `bash`；Windows 需要安装 Git for Windows（Git Bash）或 WSL 并加入系统 `PATH` |

每次运行都会把技能包解压到独立的临时目录并在结束后清理，不会修改已安装的技能文件，也不会把你的模型密钥或工作区凭据传给脚本。若电脑上缺少对应的 Python 3 或 Bash 环境，确认前就会直接提示需要安装什么。

写技能时，如果只需要读写画布或调用生成能力，优先使用内置业务操作或插件工具，见[给助手加一个工具](./plugin-development.mdx#给助手加一个工具)。

## 助手怎么用技能

助手平时只看到已安装技能的名字和简介。用户选中技能，或者助手判断用得上时，才读 `SKILL.md` 全文；`references/` 里的文件在需要时再读。所以 `SKILL.md` 写步骤，长资料放到 `references/`。

一轮对话用的是读取时固定下来的版本，技能更新不会改变进行中的任务。

## 投稿到技能市场

在 BeefTV 里准备投稿，只保存在本机；上传草稿和公开发布分别要确认。

投稿包同样接受带 `scripts/` 的技能，压缩包最多 100 MB、解压后最多 200 MB，自动检查通过并由作者确认预览后直接发布到技能市场。
