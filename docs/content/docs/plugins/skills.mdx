# 写一个技能

技能告诉创作助手一件事该怎么做。BeefTV 的技能遵循 [Agent Skills 标准](https://agentskills.io/specification)：在 Codex、Claude Code 等工具里能用的技能，放进 BeefTV 也能用。格式细节看标准，这一页只讲 BeefTV 特有的部分。

## 最小的技能

一个技能就是一个文件夹，里面有一个 `SKILL.md`：

```markdown
---
name: storyboard-review
description: 检查分镜脚本的节奏和镜头衔接。当用户要求审分镜或看看脚本有什么问题时使用。
---

# 审分镜

1. 用 `canvas_get` 读出分镜脚本。
2. 逐行检查：景别是否跳得太大，时长加起来是否超出目标。
3. 列出问题，每条写清镜号和改法。
```

`description` 决定助手什么时候想起这个技能，要写清做什么、什么时候用。

## 装进 BeefTV

| 方式 | 怎么做 |
| --- | --- |
| 其他工具装的 | 放在 `~/.agents/skills` 的技能会自动出现在「我的技能」，标着「其他工具安装」 |
| 上传 | 在技能库点「安装技能」，选 Markdown 或 ZIP 技能包 |
| GitHub | 在「安装技能」里选 GitHub，填仓库地址，可以指定分支和子目录 |
| 插件 | 放进插件包，在 `package.json` 写 `"pi": { "skills": ["./skills"] }` |
| 技能市场 | 在技能页浏览，确认后安装 |

`~/.agents/skills` 里的技能跟着目录走：要改就改文件，BeefTV 里不能编辑或删除，只能停用。不想显示这些技能时，点「其他工具的技能」关掉开关，电脑上的文件不会动。

插件带的技能跟着插件走：停用或卸载插件时一起移除。

## 规则

| 项目 | BeefTV 的规则 |
| --- | --- |
| `name` | 必填，最多 80 字，可以用中文。没写时从标题推断 |
| `description` | 必填，超过 1024 字的部分会被截掉。没写时从正文推断 |
| 包大小 | 解压后最多 200MB。不限文件数量和单个文件大小 |
| 包内容 | 只能有一个 `SKILL.md`，不能有软链接 |

这里比标准宽松：标准要求 `name` 用小写字母、数字和连字符，最多 64 个字符。要在其他工具里也能用，就按标准写。

## 脚本

包里可以带 `scripts/`。创作助手没有终端，读得到说明，但不会运行脚本。这类技能在列表和详情里标着「含脚本」。

写技能时不要让助手依赖脚本的运行结果。要让助手做事，用业务操作或者插件的助手工具，见[给助手加一个工具](./plugin-development.mdx#给助手加一个工具)。

## 助手怎么用技能

助手平时只看到已安装技能的名字和简介。用户选中技能，或者助手判断用得上时，才读 `SKILL.md` 全文；`references/` 里的文件在需要时再读。所以 `SKILL.md` 写步骤，长资料放到 `references/`。

一轮对话用的是读取时固定下来的版本，技能更新不会改变进行中的任务。

## 投稿到技能市场

在 BeefTV 里准备投稿，只保存在本机；上传草稿和提交公开审核分别要确认。

投稿包同样接受带 `scripts/` 的技能，压缩包最多 100 MB、解压后最多 200 MB，公开前需经过审核。
