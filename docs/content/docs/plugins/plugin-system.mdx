# 插件系统设计

> 状态：已实现统一插件底座（一个插件 = 一个 pi 包 + `package.json` 的 `beeftv` 字段）
>
> BeefTV 采用单一插件系统：无论是声明式模型协议包（`.beeftv-plugin`）、预装的官方插件市场（`beeftv-plugin-market`），还是从 npm、本地目录或 `.tgz` 安装的社区插件，都汇入同一套注册表（Go `internal/plugins`）、同一套画布节点目录（`capability.BuiltinRegistry()`）、同一套业务操作（`/api/ops`）与同一套技能列表（`internal/skills`）。

## 1. 核心架构与单源原则

1. **一份清单（`PluginManifest`）**：插件包既可以是包含 `manifest.json` 的 `.beeftv-plugin` 归档，也可以是标准 npm / pi 包（在 `package.json` 中声明 `beeftv` 字段、`pi.extensions` 与 `pi.skills`）。插件 ID 与版本直接取自 `package.json` 的 `name` 与 `version`（或 `manifest.json`），由 Go `internal/plugins` 使用同一个校验器校验。
2. **一份登记表（`plugin_registry`）**：装了哪些插件、是否启用、是否加载失败（`StatusInvalid` 及错误原因），唯一权威保存在 Go `internal/plugins`。安装来源包含 `official`、`system`、`uploaded` 和 `package`（npm、本地目录或 `.tgz`）。`agent-host` 和前端（`use-plugin-store`）只从 Go 读取启用列表。
3. **一个画布节点目录（`capability.BuiltinRegistry()`）**：画布节点类型定义集中在一个共享目录实例中。已启用插件声明的 `canvasNodes` 动态注册进该共享实例，确保手动添加节点与创作助手调用 `canvas_nodes_create` 遵循同一份尺寸、连线和字段校验；节点业务数据保存在 `metadata.pluginData`。
4. **一条业务写入路径**：插件在助手工具中通过 `ctx.executeTool("canvas_nodes_create", ...)`、在浏览器端通过 `host.ops.call("canvas.nodes.create", ...)` 调用 Go 业务操作。权限模式（只读 / 当前画布 / 完全访问）、付费生成确认与整组撤销全部由 Go 统一把关。
5. **一份技能列表（`internal/skills`）**：插件包的 `pi.skills` 目录登记进 `internal/skills` 的安装包体系，来源标记为对应插件；停用或卸载插件时同步移除，助手原有的技能版本固定与 `skill_load` 机制原样复用。
6. **官方 pi 组件复用**：
   - 包下载由 Go 完成：用桌面包自带的 node 与 npm 执行 `npm install --prefix`（下载源只允许 npmmirror 或 npmjs），依赖一起安装到暂存目录，经 Go 校验清单并事务提交后才替换旧版本；`agent-host` 只用 pi 官方 `DefaultPackageManager` 按单个包目录解析和加载扩展，不下载。
   - 扩展加载复用官方 `discoverAndLoadExtensions`（仅按 Go 下发的已启用插件包目录加载，不扫描宿主机用户主目录 `~/.agents/skills`，防止宿主机资源混入）。
   - 助手执行内核保持官方 `@earendil-works/pi-durable`，插件工具经 `agent-host/plugin-packages.mjs` 转换为 Durable 工具并在下一轮会话生效。

## 2. 信任模型与运行边界

- **显式安装确认**：无论从插件市场、npm 包名、本地目录还是压缩包安装插件，都由宿主页面弹出统一的安装确认框，展示插件名称、版本、来源与风险说明，第三方插件需勾选「我了解风险」；用户点取消则不执行安装。
- **直接客户端渲染（`renderer: "client"`）**：已启用插件的前端入口（`beeftv.client`）由浏览器动态加载并调用 `activate(host)`，与宿主共享同一份 React、Ant Design 与明暗主题 token。单个插件加载失败或超时（3 秒）仅将该插件标为异常，不阻塞主应用或其他插件。
- **推荐列表免责声明**：公开推荐仓库 `Sunnyender-org/beeftv-plugins` 收录社区提 PR 的插件列表，插件市场页面固定提示“被推荐列表收录不代表我们为它担保；请仅安装你信任来源的插件”。
- **静态资源路径隔离**：Go 插件文件服务仅暴露登记表内该插件包目录下的静态与模块文件，路径校验位于 `internal/plugins`，任何越界或访问 `node_modules` 的请求一律返回 404。

## 3. 插件包结构与清单

一个完整的 npm / pi 格式插件包结构如下：

```text
beeftv-plugin-sticky-note/
├── package.json
├── extensions/
│   └── index.ts          # 可选：注册 pi 助手工具（调用 ctx.executeTool）
├── skills/
│   └── sticky-note/
│       └── SKILL.md      # 可选：注册助手技能
├── client/
│   └── index.js          # 可选：浏览器界面入口，导出 activate(host)
└── README.md
```

`package.json` 示例：

```json
{
  "name": "beeftv-plugin-sticky-note",
  "version": "0.1.0",
  "type": "module",
  "keywords": ["beeftv-plugin"],
  "pi": {
    "extensions": ["./extensions/index.ts"],
    "skills": ["./skills"]
  },
  "beeftv": {
    "apiVersion": "beeftv.plugin/v2",
    "name": "画布便签",
    "client": "./client/index.js",
    "permissions": ["canvas.read", "canvas.write"],
    "contributes": {
      "canvasNodes": [
        {
          "id": "sticky-note",
          "label": "画布便签",
          "defaultTitle": "便签",
          "renderer": "client",
          "defaultSize": { "width": 240, "height": 180 }
        }
      ]
    }
  }
}
```

同时，传统 `.beeftv-plugin` ZIP 包（含根目录 `manifest.json`）继续受支持，并与 npm 插件包共用同一套清单校验逻辑。

### Provider 的 v3 请求与图片响应

`contributes.providers[]` 可在 `beeftv.plugin/v3` 清单中声明 `variables`：按数组顺序计算的纯表达式，输入为 `request`，前面的变量通过 `vars.<name>` 读取。变量仅在当前请求内存在，不共享状态。重复名称、前向引用，以及请求模板或参数校验中不存在的变量会在加载时拒绝。

```json
{
  "variables": [{ "name": "size", "value": { "$coalesce": [{ "$ref": "request.aspectRatio" }, "2K"] } }],
  "create": {
    "method": "POST",
    "path": "/images/generations",
    "defaultPathPrefix": "/api/v3",
    "body": { "size": { "$ref": "vars.size" } }
  }
}
```

`defaultPathPrefix` 是连接地址没有路径时使用的默认前缀；连接地址已有 `/v1` 等路径时保留该路径。图片响应可声明 `response.detectImageMime: true`，按实际 PNG、JPEG 或 WebP 字节确定内联图片类型；`response.stream` 指定图片 SSE 流解析规则。

## 4. 宿主接口（`activate(host)`）与挂点表

插件的 `client` 入口导出 `activate(host)`。`host` 提供的核心接口如下：

| 接口 | 作用 |
| --- | --- |
| `host.contribute(slot, payload)` | 向指定挂点注册界面扩展，返回卸载函数；插件停用或卸载时宿主按插件 ID 自动撤销全部挂载 |
| `host.ops.call(operation, params)` | 调用后端 `/api/ops` 业务操作，遵循统一权限、付费确认与撤销规则 |
| `host.events.on(event, handler)` | 订阅宿主状态变化事件，返回取消订阅函数 |
| `host.React` | 与宿主共用的 React |
| `host.ui` | `notify` 提示、`navigate` 跳转与 `requestInstallPlugin` 安装确认触发器 |
| `host.storage` / `host.config` | 插件命名空间下的键值存储与用户在插件中心填写的配置项 |
| `host.context.getCanvasId()` | 当前打开的画布 ID；画布 revision 用 `canvas.get` 操作读取 |

### 4.1 界面扩展位（挂点表）

| 区域 | 挂点名称 | 插件可贡献内容 |
| --- | --- | --- |

| 画布 | `canvas.toolbar.main` | 画布底部主工具栏按钮 |

| 画布 | `canvas.toolbar.nodeHover` | 单个节点悬停工具栏按钮 |
| 画布 | `canvas.contextMenu` | 画布空白处与节点上的右键菜单项 |

| 素材 | `assets.source` | 外部素材库连接器（如 Eagle 素材源） |
| 素材 | `assets.itemActions` | 素材卡片与素材详情弹窗上的扩展操作按钮 |

| 全局 | `app.sidebar` | 工作区左侧全局导航入口 |

### 4.2 宿主事件表

| 事件名称 | 触发时机 | 回调参数 |
| --- | --- | --- |
| `generation.submitted` | 画布节点的生成任务已提交 | `{ nodeId, nodeType, model?, prompt, taskId? }` |
| `generation.completed` | 生成任务完成 | `{ nodeId, nodeType }` |
| `generation.failed` | 生成任务失败 | `{ nodeId, nodeType, error, taskId? }` |
| `assets.imported` | 素材导入完成 | `{ assets: [{ id, name, type, url }] }` |
| `assistant.turnCompleted` | 创作助手一轮对话执行结束 | `{ canvasId?, sessionId?, turnId?, status }` |

画布打开、画布内容变化、选中变化三类事件尚未接入。

## 5. 内置功能与样板插件

- **内置能力统一走挂点**：提示词优化器（`canvas.promptActions`）、Eagle 素材库页面与设置（`app.page`、`assets.source`、`app.settings`）、AI 审美批改节点（`canvas.node`）均通过统一挂点机制接入。
- **官方插件市场（`beeftv-plugin-market`）与内置渠道插件（`beeftv-plugin-ll2`）**：随桌面包预装并默认启用（通过 `plugin-packages/bundled-plugin-dirs.txt` 打包进 `agent-host/bundled-plugins/`）；插件市场挂载于 `pluginCenter.section`，支持从 `Sunnyender-org/beeftv-plugins`（含国内 jsDelivr / GitHub 镜像加速链与本地离线缓存）读取推荐列表、预览远程 `README.md`、按 `beeftv-plugin` 检索 npm 社区插件并在线安装。
- **官方与社区扩展插件（按需在线安装，不随桌面客户端捆绑）**：
  - `beeftv-plugin-character-replacement`：「AI 角色替换工作室」短剧二阶段角色替换与全片时间轴回插官方插件，作为插件市场精选推荐插件提供在线下载安装。
  - `beeftv-plugin-sticky-note`：画布便签开发模板插件（含自定义节点、助手工具与技能）。
  - `beeftv-plugin-ecommerce-hero`：「一键商品主图」电商开发样板插件。
  - `beeftv-plugin-slot-test`：往每个挂点各挂一项、订阅全部事件的开发自检插件，不在推荐列表里，也不随桌面发布包附带。

## 6. Eagle 外部素材来源方案

Eagle 插件的主分类是“素材与数据连接器”，通过 `assets.source`、`app.page`（`/p/eagle-asset-connector`）和 `app.settings` 挂点接入：

- 使用 Eagle 本地 API（默认 `http://127.0.0.1:41595`）检查服务并读取当前素材库。
- 在素材页或独立插件页按 Eagle 的父子文件树浏览和搜索文件，通过后端本地桥接安全读取媒体字节。
- 支持在当前 Eagle 文件夹中新建文件夹，将本地图片、视频和音频写入 Eagle，或在插件设置中开启生成结果自动归档。
